# LearnLab: React, Java Streams and SQL Practice — Build Brief

**Goal:** A local interactive site that teaches React from basics to advanced through lessons and a live editor with preview, and drills 500 Java Stream API and 200 SQL interview questions (beginner to advanced). Each item has an editor, a Run button with output, an output check, and a View Answer button with an explanation.

**Context:** This is a new sub-project in `C:\AutoAp\learnlab`, independent of the AutoAp extension. Only Python 3.13 is installed. A portable JDK 21 is downloaded into `.tools/`.

**Approach:**
- **Server:** A FastAPI app serves the static UI and three APIs:
  - `GET /api/bank/{stream|sql}` returns the question bank.
  - `POST /api/run/java` wraps the user's snippet in a harness with shared sample data and runs it with `java Main.java` in a temp directory, with a 10-second timeout and a 64KB output cap.
  - `POST /api/run/sql` runs the query on a fresh in-memory SQLite database seeded with an HR and sales schema, with statement limits and a timeout via the progress handler.
  - Output is compared with the expected output. SQL comparisons ignore row order unless the reference query uses ORDER BY.
- **React:** The JSX runs entirely in the browser, in a sandboxed `iframe` using vendored React 18 UMD and Babel standalone. There are about 30 lessons from basics to advanced: JSX, props, state, events, lists and keys, forms, effects, refs, memo/useMemo/useCallback, useReducer, context, custom hooks, portals, error boundaries, lazy/Suspense, useTransition/useDeferredValue, useId, useSyncExternalStore, useImperativeHandle, compound components, render props, HOCs, state machines, virtualization, optimistic UI and performance. Each lesson has an explanation, a live demo, an exercise with automatic DOM checks run in the iframe, and an answer with an explanation.
- **Question banks:** About 100 Stream and 60 SQL core questions are hand-written. Generated variants (changed thresholds, fields and groupings) bring the totals to 500 and 200, tagged beginner, intermediate or advanced. `build_banks.py` computes every expected output by running the reference answers (Java runs as one batch harness) and writes `data/*.json`.
- **UI:** A minimal single-page app with three tabs. It has a filterable question list (level, topic and search), progress stored in `localStorage`, a split editor/output layout and keyboard shortcuts.
- **Rejected alternatives:**
  - A pure-browser Java interpreter (CheerpJ/TeaVM): too heavy for a lightweight tool, and it needs a CDN.
  - Monaco Editor: too heavy. A textarea with a line-number gutter, Tab support and Ctrl+Enter to run fits "lightweight".

**File map:**
- `learnlab/app/main.py`: the FastAPI app, security middleware (token, Host and Origin checks) and routes.
- `learnlab/app/java_runner.py`: harness wrapping, the JDK subprocess, timeout and output cap.
- `learnlab/app/sql_runner.py`: the seeded SQLite database, query execution and result comparison.
- `learnlab/app/seed.sql`: the sample schema and data.
- `learnlab/app/banks/stream_bank.py` and `learnlab/app/banks/sql_bank.py`: core questions and variant generators.
- `learnlab/build_banks.py`: produces `data/stream.json` and `data/sql.json` with verified outputs.
- `learnlab/static/`: `index.html`, `styles.css`, `app.js`, `react-lessons.js`, `editor.js`, `vendor/` (react, react-dom, babel) and `assets/logo.svg`.
- `learnlab/tests/`: pytest tests for the runners, security and bank integrity.
- `learnlab/run.ps1`: sets `JAVA_HOME` and starts the server.
- `learnlab/README.md`: usage.

**Security & observability impact:**
- The server runs arbitrary user code locally, so it binds to `127.0.0.1` only.
- A per-start random token is injected into the page and required in the `X-LearnLab-Token` header; requests with a non-local Host or a foreign Origin are rejected (CSRF and DNS rebinding).
- Runs have a timeout and an output cap. SQLite is in-memory with `ATTACH` disabled through an authorizer.
- `structlog` JSON logs record only the event, duration and status. User code is never logged. `pip-audit` runs before completion.

**Constitution check:** Conforms to `learnlab/docs/constitution.md`. The AutoAp constitution (Chrome extension) does not cover this sub-project.

**Out of scope:** Accounts, cloud hosting, other Java APIs beyond the Stream/Collections harness, and SQL dialects other than SQLite (questions avoid dialect-specific syntax where possible and note it otherwise).
